## 合约做了什么

Counter 是一个教学用的计数器，源码只有十几行：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract Counter {
    uint256 public count;
    address public owner;
    event Incremented(address indexed by, uint256 newCount);

    constructor() { owner = msg.sender; }

    function increment() external {
        count += 1;
        emit Incremented(msg.sender, count);
    }

    function reset() external {
        require(msg.sender == owner, "not owner");
        count = 0;
    }
}
```

任何人都能 `increment`（加一并发出 `Incremented` 事件），只有部署者 `owner` 能 `reset`（清零）。实际用 solc 0.8.34 编译。

## 从数字里能学到什么

- **链在替你记账**：`count` 和 `owner` 都写在链上，事件日志也在链上。要改状态必须自己付 gas。
- **部署远比调用贵**：部署用了 1,652,641 gas，reset 只用 23,626 gas。主要成本是把合约代码写进链上状态，而不是那几行加减逻辑。
- **同一个函数的 gas 会变**：从 0 变成 1 的 increment 用了 127,229 gas，从 1 变成 2 只用了 29,309 gas。原因是存储槽从零写成非零更贵，已经非零再改就便宜得多。
- **已确认的交易不能撤销**：reset 把数字清零，但抹不掉之前 increment 的交易和事件，历史仍在。
- **这段合约不能再加功能**：想增加批量操作或升级能力，必须在部署时就采用可升级模式——这直接引出了后面的 UBOX（第 13 章）。

## 生活对应

把它想成一家店门口「所有合作商户都能核对」的公共计数器：调用一次，计数变化一次。如果计数涉及活动抽奖总次数、公开任务完成次数，链上计数能减少「单方改数」的争议。但它证明不了柜台前真的来过一个人。
