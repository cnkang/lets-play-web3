<p class="lead">A "<Term id="token">token</Term>" is first of all a set of account balances and rules maintained by a contract, not an asset that must rise in value.</p>

## What ERC-20 is

**ERC-20** is the most common interface standard for fungible tokens on <Term id="ethereum">Ethereum</Term>. It defines a set of functions such as:

- `balanceOf(account)`: an account's balance (read-only)
- `transfer(to, amount)`: the holder sends tokens
- `approve(spender, amount)` and `allowance(owner, spender)`: grant and look up an allowance (Chapter 10)
- `transferFrom(owner, to, amount)`: an approved <Term id="spender">spender</Term> moves tokens within the allowance

For beginners it is more useful to picture a token as "points shared by a group of partner shops" than as "an asset that goes up". A standard interface is only an agreement about how to interact: a token can still have special restrictions, fees or admin powers. Being "ERC-20 compliant" does not mean the economics are the same.

<T label="ERC-20 operations and everyday analogies">

| On-chain call | Everyday analogy | What you should observe |
| --- | --- | --- |
| `balanceOf(A)` | Look up A's points | Returns data; no transaction needed |
| `transfer(B, 5)` | A gives B 5 points | A goes down, B goes up |
| `approve(S, 100)` | Allow a checkout system to deduct up to 100 points | Balances unchanged, allowance changes |
| `transferFrom(A, B, 5)` | The approved system deducts 5 points | Balances change, allowance usually goes down |
| `burn(5)` (if supported) | Points cancelled for good | Total supply goes down |

</T>

## Sent to a keyless address: gone for good

The 1,000 MBox went to this demo address:

<Addr a="0x878fFf967331D01E97c8DdCD76C3Dd97333BcA6E" />

**No <Term id="private-key">private key</Term> for this address was ever stored**, and it holds no <Term id="sepeth">SepETH</Term>. Without a private key nobody can sign a transfer out, and confirmed <Term id="transaction">transactions</Term> cannot be reversed. So these 1,000 MBox are **locked forever and cannot be recovered**.

<Callout type="danger" title="Do not send anything else to this address">

This was a deliberate teaching point, not an accident. Please **do not** send any more tokens or test ETH to `0x878fFf967331D01E97c8DdCD76C3Dd97333BcA6E`: anything sent there is locked the same way. In real life, sending assets to a wrong or uncontrolled address has exactly the same result.

</Callout>

## Names and symbols are not unique: trust the address, not the name

`name()` and `symbol()` are just **unregistered strings** returned by the contract. There is no on-chain registry of token names. Anyone can deploy another contract with exactly the same name and symbol, and <Term id="wallet">wallets</Term> will display it the same way.

**The only way to identify a token is its contract address.** Seeing "MBox" does not mean it is this book's contract; only the address `0xc4B187783f074111EbeFC50B9a1901f2a4F94630` does.
