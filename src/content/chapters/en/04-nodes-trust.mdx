<p class="lead">"Hard for one party to tamper with" does not mean "always true, always safe, never changeable".</p>

## What a node is

A **node** is a computer running <Term id="blockchain">blockchain</Term> software. Different nodes can check the same transaction against the same rules. What you can look up depends on what data a node keeps. For example, an <Term id="archive-node">archive node</Term> can tell you what an account’s balance was at a particular block long ago.

The labs in this book used a **free public <Term id="rpc">RPC</Term> node** (a web address you use to query a node):

```text
https://ethereum-sepolia-rpc.publicnode.com
```

It needs no <Term id="api-key">API key</Term>. The trade-offs are limited speed and reliability and **no archive data**: asking for the state at an old block may fail. That is why the Phase-0 review rebuilt the upgrade path locally instead of paying for an archive node (see Chapter 15).

## Everyday analogy: a shared mall checkout

Analogies help understanding; they are not strict definitions. Suppose three shops share a points ledger that no single shop can rewrite. Shop A claims it added 10 points for a customer; the other shops can check by the rules whether that change is valid.

But that does not prove the customer **really** bought anything. Facts that happen offline still have to be entered by a trusted person, device or institution.

## Four things a blockchain does not solve on its own

1. **Real-world truth** (the <Term id="oracle">oracle</Term> problem): a false report made before data goes on-chain is still recorded faithfully.
2. **Privacy**: addresses and interactions on a public chain can usually be traced by anyone.
3. **Lost keys**: losing a <Term id="private-key">private key</Term> is not like forgetting a website password. There is no "reset password" button.
4. **Buggy contracts**: code can be executed in public, and it can also execute **the wrong logic** in public.

<Callout type="warn" title="Easy to mix up">

"Hard to tamper with unilaterally" does not mean "always true", "always safe" or "never changeable". In Chapter 13 you will see that the admin of an <Term id="upgradeable">upgradeable contract</Term> can legitimately change the rules behind the same address.

</Callout>

## Where this shows up in the labs

- Chapter 9: 1,000 MBox were sent to an <Term id="address">address</Term> with **no known usable private key**, so they cannot practically be moved: an extreme case of a lost key.
- Chapters 14–15: the Phase-0 review still found a Medium-severity issue. Putting code on-chain does not make design flaws disappear.
