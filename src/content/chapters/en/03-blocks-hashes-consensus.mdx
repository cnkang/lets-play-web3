<p class="lead">How would you notice an old record had been edited? Start with pages that refer to earlier pages, then ask how everyone agrees which record to accept.</p>

## A bound ledger book

Bind each day's records into a book: every page lists that day's <Term id="transaction">transactions</Term> and time, and **copies a summary of the previous page**.

A **hash** works like a fingerprint for a page’s contents. Change “10 points” to “100 points” on page 2 and its fingerprint changes. Page 3 still holds the old fingerprint for page 2. To hide the edit, you would have to update page 3. That changes its fingerprint too, so you would have to update page 4, and so on.

<Figure name="blocks" n="1" alt="Three blocks left to right; each holds the previous block's fingerprint, its transactions and its own fingerprint, with arrows linking each fingerprint into the next block.">
<Term id="block">Blocks</Term> hold transaction data and are linked by the previous block's hash. H(…) in the figure is a symbol, not a real value.
</Figure>

## Why is consensus still needed?

If you keep a hash-linked log on your own, you can simply rewrite it from the start and recompute every fingerprint. Hashes alone cannot stop a complete rewrite.

The real key of a blockchain is that **many independent <Term id="node">nodes</Term> follow the same rules and jointly decide which history to accept**. Those rules are the <Term id="consensus">consensus</Term> mechanism, and different networks use different ones.

## Proof of stake on Ethereum

<Term id="ethereum">Ethereum</Term> currently uses **proof of stake** (PoS). Roughly:

- people who want to propose and validate blocks (validators) must **stake** <Term id="eth">ETH</Term> as a deposit;
- the protocol selects a validator to propose each block, and other validators check that the block follows the rules and **attest** to it;
- rule-breaking can be penalised, for example by losing part of the stake.

So it is **not** simply "every computer votes on who is right". Voting weight and eligibility come from stake and protocol rules, every node independently checks that transactions and blocks are valid, and honest nodes reject invalid blocks.

<Callout type="note" title="Key idea">

Hashes help **detect** changes; consensus rules and distributed validation decide **which state is accepted**. You need both.

</Callout>
